## 1. 总体结构

三条功能都围绕现有的“每个 chunk 一个 Mesh + 一个 GameObject”体系实现，没有改数据格式，也没有引入 Addressables / Burst / InputSystem / uGUI。

主要运行链路：

```text
VoxelWorld
  ├─ 读取 manifest / blocks / .vxcell
  ├─ 流式生成 chunk Mesh
  ├─ 保存 live chunk 的 VxChunk 数据（chunkData）
  ├─ 生成 A 的岩层包络网格（VoxelEnvelope）
  ├─ 生成 B 的剖面盖面网格（VoxelSectionCap）
  └─ OnGUI 调用 VoxelDisplayController.DrawHud()

SectionViewport
  ├─ 第二台正交相机 + 512×512 RenderTexture
  ├─ 剖面视口绘制、缩放、平移
  └─ 仅在剖面相机渲染期间打开 shader 剖切

VoxelDisplayController
  ├─ A/B/C 的 IMGUI 面板
  ├─ 推送 shader 全局参数
  ├─ 维护剖面平面
  ├─ 触发 A 包络 / C 筛选重建
  └─ 控制剖面相机与盖面
```

## 2. 为什么需要 Shader

### 2.1 Shader 的作用

Shader 是 GPU 上执行的渲染程序。本项目的体素数量很大，很多效果如果每帧在 CPU 上改 Mesh 会非常慢，因此把“每像素/每顶点”的判断放到 shader：

- 顶点阶段：
  - 把 chunk 的局部坐标变换到裁剪空间；
  - 传递顶点色、世界坐标、雾参数。
- 片元阶段：
  - 按世界坐标判断是否在剖面平面的保留侧；
  - 按到主相机的距离做 4×4 Bayer 点阵虚化；
  - 叠加雾；
  - 输出最终颜色。

Shader 不能创建几何体。它只能对已有 Mesh 的顶点/片元做处理。  
所以“把方块切成新的截面”“显示剖面经过的方块”这类需要新面的功能，必须由 CPU 生成 Mesh，再交给 shader 渲染。

### 2.2 A/B/C 需要三个 Shader 吗？

不需要。当前实现只有 **一个 shader 文件**：

```text
Assets/Shaders/VoxelVertexColor.shader
```

它通过材质属性和全局 uniform 支持不同角色：

| 材质 | 用途 | 关键属性 |
|---|---|---|
| `Voxel.mat` | 普通 chunk 表面 | `Cull Back`、`_NoFade=0`、`_SectionCap=0` |
| `VoxelDoubleSided.mat` | B 剖面时使用的双面版本 | `Cull Off`、`_NoFade=0`、`_SectionCap=0` |
| `VoxelEnvelope.mat` | A 的岩层包络 | `Cull Off`、`_NoFade=1`、`_SectionCap=0` |
| `VoxelSectionCap.mat` | B 的剖面盖面 | `Cull Off`、`_NoFade=1`、`_SectionCap=1` |

其中：

- `_NoFade=1`：跳过 A 的透明化，用于包络/盖面这类必须不透明的表面。
- `_SectionCap=1`：跳过 B 的剖切 clip，避免盖面自己也被裁掉。
- `_CullMode`：控制单面/双面。

因此不是“三个功能三个 shader”，而是：

> **一个通用体素 shader + 多个材质配置 + 少量全局 uniform。**

### 2.3 为什么需要多个 `.mat`

Unity 的 `.mat` 是“shader + 一组属性值”的资产。不同渲染角色需要不同状态：

- 普通表面：单面、可虚化、参与剖面裁切；
- 剖面双面：双面、可虚化、参与剖面裁切；
- A 包络：双面、不虚化、不参与 A 的透明化；
- B 盖面：双面、不虚化、不被剖面裁切。

这些状态无法只靠一个材质同时满足。拆成多个 `.mat` 后：

- chunk Mesh 可以共用，不需要复制几何；
- 切换 B 时只换共享材质，不重建网格；
- 每个材质都是资产，能保证 shader 在 APK 中被引用，不会出现运行时 `new Material` 的 shader 丢失问题。

## 3. 功能 A：相机半径虚化

### 3.1 目标行为

- 以主相机为中心，半径内普通方块表面半透明；
- 半径外保持不透明；
- 透过半透明表面能看到半径边界处的岩层，而不是虚空；
- 从地表向下看，可以看到地下的岩层包络；
- 地下洞穴/水面/地面只要在半径内，也按透明度虚化；
- 包络面本身不受透明度滑条影响。

### 3.2 实现

1. **普通表面渐隐**
   - 由 shader 的 `_FadeEnabled`、`_FadeRadius`、`_FadeStrength`、`_FadeSoftness`、`_FadeCenter` 控制。
   - 片元到主相机的距离决定 `alpha`；
   - 用 4×4 Bayer 阈值 `clip(alpha - threshold)` 做点阵透明；
   - 仍走 Opaque，不排序、不改渲染队列。

2. **不透明岩层包络**
   - `VoxelWorld.SetEnvelope()` 每帧被调用。
   - 相机跨过方块或半径变化时，生成 `VoxelEnvelope` 网格。
   - 只生成“球外实心块朝向球内、且球内邻居也是实心块”的面。
   - 颜色取球外方块颜色，法线朝向球内。
   - 材质 `VoxelEnvelope.mat`：`Cull Off`、`_NoFade=1`。
   - 这样虚化普通表面后，露出来的是不透明的岩石层，而不是背景/虚空。

3. **A 与 C 的同步**
   - C 正在增量重建可见集时，A 包络先隐藏；
   - C 完成后，A 包络按新的 `currentVisibility` 重建；
   - 避免两套可见集混用。

## 4. 功能 B：剖面 + 展示框

### 4.1 目标行为

- 只在展示框里剖切，主视角世界不能被裁掉；
- 展示框显示剖面经过的方块截面，而不是只切掉一半；
- 支持 X / Y / Z 轴；
- 支持任意方向平面（偏航/俯仰/沿法线偏移）；
- 展示框内可缩放、平移；
- 剖面相机渲染同一批 chunk，但 draw call 只增加在展示框。

### 4.2 只在展示框剖切

- `VoxelDisplayController.PushGlobals()` 每帧把 `_SectionEnabled` 置 0，主视角不裁切。
- `SectionViewport` 通过 `RenderPipelineManager.beginCameraRendering` / `endCameraRendering`：
  - 剖面相机开始渲染时置 `_SectionEnabled=1`；
  - 结束渲染时置 0。
- `SectionCameraClip.cs` 作为兼容兜底，也在剖面相机的 `OnPreRender/OnPostRender` 设置同样开关。
- 因此主视角永远看到完整世界，只有第二相机看到裁切。

### 4.3 剖面相机与展示框

- 第二台正交相机，`orthographicSize = 64 / zoom`；
- 512×512 RenderTexture；
- 相机位置在剖面平面“被切掉”的一侧，正对保留侧；
- 展示框用 IMGUI 绘制 RT，支持拖动平移、滚轮/±缩放；
- 关闭 B 时禁用相机并释放 RT。

### 4.4 剖面盖面

- `VoxelWorld.SetSectionCap()` 在剖面视口打开时生成 `VoxelSectionCap` 网格。
- 盖面只生成剖面视口覆盖范围内、平面经过的方块截面：
  - X/Y/Z 轴：按平面所在方块层生成四边形；
  - 任意方向：计算平面与体素立方体的相交多边形，排序后三角化。
- 盖面材质 `VoxelSectionCap.mat`：
  - `_SectionCap=1`：跳过剖切 clip；
  - `_NoFade=1`：不受 A 虚化影响；
  - `Cull Off`：从两侧都可见。
- 盖面对象放在 `SectionCapLayer = 8`：
  - 主相机 `cullingMask` 排除该层；
  - 剖面相机 `cullingMask` 包含该层；
  - 所以盖面只出现在小窗口，主视角看不到。

## 5. 功能 C：方块筛选

### 5.1 目标行为

- 支持“隐藏选中”和“仅显示选中”两种模式；
- 隐藏水面后，水面消失且不出现透空；
- 只显示铁矿时，每个连续矿脉是完整封闭的浮空岛；
- 恢复全部显示后，画面与原始一致；
- 切换不重建整张地图（但需要重建可见集合的 chunk）。

### 5.2 实现

- 不再使用 128-bit shader 掩码隐藏。掩码只能隐藏已有面，无法补出被剔除的相邻实心面。
- 改为 **CPU 可见集重建**：
  1. `VoxelDisplayController` 维护 `selected[]` 和 `filterMode`；
  2. 点击“应用筛选”时构造 `bool[] visible`；
  3. `VoxelWorld.RebuildVisibility(visible)` 对 live chunk 逐个重建 Mesh；
  4. `ChunkMesher.BuildInto()` 只生成“可见方块与不可见邻居之间的面”。
- 结果：
  - 可见集合的边界被完整生成；
  - 隐藏水后，湖床/岸壁会重新出面；
  - 只显示铁矿时，矿脉是封闭壳。
- 重建采用协程，每帧 2 个 chunk，避免一次性长时间冻结；
- 重建期间 UI 显示“重建中 x/y”；
- `chunkData` 保留 live chunk 的体素数据，避免重复读取 `.vxcell`；
- C 重建期间 A 包络/B 盖面会先隐藏，完成后按同一可见集重建。

```text

Assets/Scripts/Voxel/VoxelWorld.cs              RebuildVisibility / RebuildChunk / chunkData
```

## 6. Shader 与材质的关系

### 6.1 Shader 全局参数

`VoxelDisplayController` 每帧推送：

```text
_SectionNormal / _SectionD / _SectionEnabled   剖面平面
_FadeEnabled / _FadeRadius / _FadeStrength
_FadeSoftness / _FadeCenter                    A 虚化
```

材质属性：

```text
_CullMode      单面/双面
_NoFade        1 = 跳过 A 虚化（包络、盖面）
_SectionCap    1 = 跳过 B 裁切（盖面）
_Tint          顶点色乘数
```

### 6.2 为什么不把所有逻辑塞进一个材质

因为不同网格需要不同的渲染状态：

- 普通 chunk：单面 + 可虚化 + 参与剖切；
- 包络：双面 + 不虚化；
- 盖面：双面 + 不虚化 + 不参与剖切；
- 剖面双面：双面 + 可虚化 + 参与剖切。

所以采用“一个 shader + 多个材质”的方式，而不是一个材质打天下。

## 9. 已知限制

1. **C 重建成本**
   - 应用筛选时逐 chunk 重建，约几十帧完成；
   - 2 chunk/帧可调；大半径/复杂选择会更慢。

2. **A 包络**
   - 包络是“球外实心块朝向球内”的边界层，不是完整体积；
   - 半径边界随相机跨方块更新，默认每格重建一次；
   - 半径很大时体积扫描成本上升。

3. **B 盖面**
   - 只生成展示框覆盖范围内的截面，不是整张无限平面；
   - 展示框平移到未加载 chunk 区域时，截面可能为空；
   - 任意方向平面在 1× 缩放时扫描范围最大，可能较重；
   - 剖面相机开启时主视角仍使用双面材质（但不裁切）。

4. **性能**
   - A 包络、B 盖面、C 筛选重建都在主线程；
   - 需要真机 PerfDog/Profiler 进一步确认大半径和快速移动时的帧时间。
